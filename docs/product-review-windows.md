# Windows 与双端产品评审

日期：2026-10-13。评审对象：README、产品范围、当前进度与双端方案。本文是独立产品评审和开发验收建议，不代表真机验证结论。用户已授权服务器开发与同仓库结构重构；名称继续使用 KeepMyMacAwake，Windows 标注「Windows 开发预览」。

## 核心判断

核心任务是：用户睡前或离开电脑前，让正在运行的 AI 长任务获得持续运行的条件，回来后查看任务结果。防闲置休眠、合盖和计时是实现这个目标的能力。产品不替 AI 执行任务、不识别任意任务是否完成，也不保证完成、网络连续或系统更新不重启。

两端应统一操作、场景意图、结束规则和停止原因；能力状态需要如实区别。本轮适合交付接电、开盖的 Windows 普通保活开发预览及本地交接，合盖恢复与未验证的电池支持留待真机。完成服务器编码不等于完成 Windows 用户发行。

## P0：影响是否可以启动或宣称支持

| 问题 | 用户后果 | 本轮建议与验收门槛 |
| --- | --- | --- |
| 普通请求被误认为可以合盖 | 用户看到运行中就合盖，长任务仍被中断 | Windows 合盖保持不可用，点击场景显示明确原因。启动普通模式前说明「请保持开盖；本版不支持合盖」。就绪不能只由 API 成功推导 |
| 电池与 Modern Standby 被当成普通保活 | 定时八小时但几分钟后系统停止接受请求 | 预览默认并限制接电；拔电停止，供电未知不能启动或继续。电池能力需按睡眠模型分别验收，不能通过重复请求绕过系统策略 |
| Windows 伪热状态或无条件复用 Mac 热要求 | 显示「温度正常」误导用户；或所有普通场景永远不能启动 | 没有来源时显示「应用热保护不可用」。在决策文档明确普通预览所用能力配置：接电开盖、无应用级热保护、保留系统保护、合盖关闭。若当前规则明确要求热保护，则阻止启动；不得只删掉监控检查或提示代替必需保护 |
| 场景自动降级 | 有网时原意是电池合盖，软件却在开盖接电模式启动 | 保留场景名称与意图；不能满足的场景不可启动。可提供用户主动选择日常模式的入口，不能自动切换或取消条件 |
| 锁屏语义没有证据 | 用户睡前锁屏后不知任务还能否持续 | 不模拟输入、不改锁屏策略；记录锁屏持续任务心跳。PowerToys 的限制是该产品说明，不能推导所有 Windows 实现都不行，也不能推导本实现一定可行 |
| 截止和恢复被 UI 掩盖 | 机器睡眠再恢复时，过期会话意外续跑；恢复失败却显示已完成 | 恢复先重验截止与保护，不重开过期会话。展示最近停止时间、原因与恢复结果。未来合盖服务在异常恢复未确认前不显示待机成功、不允许新租约 |
| 同品牌宣传超出交付 | 用户从 Mac 合盖宣传下载 Windows 后发现核心功能不可用 | Windows 下载页和窗口注明开发预览、接电开盖及已知限制；没有真机记录前不宣称已支持。Mac 已验收项与未验收项也单列 |

微软说明普通系统请求防止闲置睡眠，但主动睡眠和合盖属于不同边界；Modern Standby 电池上的系统及执行请求在系统睡眠超时后五分钟终止。这是采用接电预览边界的官方依据，而非本项目已完成的设备测试。[PowerSetRequest](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-powersetrequest)

微软明确说明 `Win32_TemperatureProbe.CurrentReading` 当前不提供实时读数，因此 WMI 类存在或查询成功不构成有效热保护。其他硬件来源仍需单独研究和验证，不能据此声称 Windows 永远无法取得热数据。[Win32_TemperatureProbe](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/win32-temperatureprobe)

合盖动作有专门系统设置；未来如果修改，必须拥有独立恢复、写前基线、读回和机型验证。不能让用户手动永久改为不执行任何操作，再把它算作应用已经支持临时合盖。[Lid switch close action](https://learn.microsoft.com/en-us/windows-hardware/customize/power-settings/power-button-and-lid-settings-lid-switch-close-action)

## P1：影响普通用户是否愿意留下它

1. **夜间应该容易确认结束时刻。** 除剩余时间外显示「预计 07:30 结束」，无限时显示「直到手动停止」。夜间首选接电开盖；自动熄屏更适合睡觉。为双端一致保留现有柔光选项，但明示它是画面遮罩，不降低硬件背光；不要通过系统名称误导节能效果。
2. **启动前说明当前配置，启动后说明实际状态。** 一行显示「开盖 · 接电 · 不要求网络 · 8 小时」。请求已持有是运行条件状态；未检测 AI 任务时不得显示「AI 正在工作」「任务已完成」。网络路径可用不等于服务连通，离线任务无需联网。
3. **结束原因需要留下来。** 到期、用户停止、拔电、网络路径中断、供电未知、系统睡眠、后端失败分开。建议托盘提示和控制页保留最后一次结果；正常结束无需弹出抢焦点窗口。断网恢复、重新接电或重启不自动重新开启。
4. **关窗口与退出要清楚。** 关闭控制窗口留在托盘；首次关闭时简短提示去哪里找回。托盘必须有打开、停止和退出。退出停止保活；启动项只打开待机应用。
5. **偏好不能改写当前承诺。** 活动会话的截止与实际配置明确显示；变更偏好仅用于下次，或通过显式停止重开应用。加十五分钟单独操作，不能因切场景或编辑时长意外重置计时。
6. **能力差异应可理解。** 不把灰掉的按钮当说明。未开放合盖时显示「Windows 合盖尚未完成验证，本版请保持开盖」；热栏显示「应用热保护不可用」，电源未知显示未知，桌面机无电池显示「无电池」而非电量零。
7. **升级和卸载必须有完整图形路径。** 普通预览不写系统电源设置、不安装恢复服务时说明这一范围；未来服务版卸载必须先停止、确认恢复，再移除服务和文件。不能让普通用户运行命令才能撤销设置。
8. **跨端视觉一致服务于理解。** 共用杯子、暖铜色、四场景、固定启停位置；保留 Windows 键盘导航、缩放、屏幕阅读和托盘习惯。不同状态使用文本或形状辅助，不能只靠颜色。

## 同类产品参考与差异

PowerToys Awake 已提供无限、时段及截止保活、托盘入口和可选常亮；这些是用户可能已有的基本预期。官方同时注明其锁屏限制。本项目可以围绕睡前配置清晰、停止原因、双端同体验和未来临时合盖恢复建立价值，但锁屏优势与合盖优势必须等本实现完成验证后才对外使用。此处是从公开资料作出的产品判断，没有完成用户访谈或需求规模验证。[PowerToys Awake](https://learn.microsoft.com/en-us/windows/powertoys/awake)

## 双端验收场景

| 场景 | 共用结果 | Windows 真机补充 |
| --- | --- | --- |
| 睡前开盖接电启动八小时 | 启动成功后计时，允许用户锁屏；到期撤销保活 | 分别观察开盖熄屏、锁屏、任务心跳持续，至少一次真实夜间长跑 |
| 一分钟会话到期后再次续时 | 拒绝续活，保持停止 | 确认系统请求实际释放 |
| 网络条件未开启，网络中断 | 不因断网停止 | 离线任务持续运行；不能依据网络断开推断任务失败 |
| 网络条件开启，路径中断后恢复 | 停止并保留原因，不自动重启 | VPN、Wi-Fi、网线切换分别观察，结论限定检测范围 |
| 仅接电中拔电或数据未知 | 停止，显示具体原因 | Modern Standby 与传统睡眠设备分别记录 |
| 关闭窗口、退出、强杀、重启 | 关窗口常驻；退出/强杀释放普通请求；重启不自动保活 | 实际查验请求与进程生命周期；未来合盖还要独立恢复服务验证 |
| 请求不可用、未开放合盖 | 不显示已开启，不默默改场景 | 管理设备显示原因，不绕过策略 |
| 睡眠后恢复且截止已过 | 已结束，不重新申请旧会话 | 主动睡眠、电源键、系统恢复分别检查 |
| 夜间多屏与缩放变化 | 不阻断停止入口，不闪亮重建，不残留遮罩 | 多 DPI、外屏插拔、锁屏、全屏组合人工验收 |

服务器纯逻辑测试与交叉编译可以验证状态规则和代码完整性，不能替代以上原生或物理结果。交接记录需写明提交号、机型、系统构建、睡眠模型、供电、显示器、时长、请求/设置前后值和连续任务证据。

## 建议交付顺序

1. 同仓库拆分 `macos/`、`windows/`、`specs/`，保留现有 Mac 构建入口和行为；共用场景规范及停止原因测试数据。
2. 实现 Windows 接电开盖普通预览、托盘控制、计时与续时、屏幕模式、网络条件、偏好及能力阻止；不安装服务、不写合盖设置。
3. 服务器完成能执行的测试、Windows 交叉编译与打包脚本，留下原生验证和图形安装包任务；结果如实写进状态。
4. Windows 本地完成锁屏和夜间长跑；再研究恢复服务、可靠热来源、Modern Standby 边界。满足门槛后再开放合盖，不为了界面对齐提前开启。

名称讨论不阻塞本轮；`KeepMyMacAwake · Windows 开发预览` 可作为工作展示名，未来统一品牌时再规划安装标识迁移。

## Windows UI 落地后的代码产品验收

| 优先级 | 具体触发与源码位置 | 修复状态与剩余验收 |
| --- | --- | --- |
| P0 | `MainViewModel.Toggle()` 原先优先显示旧 `session.Error` / `LastStopReason`，覆盖当前启动错误 | 源码已修复：优先当前异常，当前保护理由翻译；仅待恢复时附加释放错误。Extend 因保护停止也显示真实停止原因。剩余：Windows 执行注入检查，实际操作到期后再选合盖、后端失败后输入无效分钟 |
| P1 | `RemainingText` 待机原先恒为「准备就绪」，未支持配置容易误读为可启动 | 源码已修复：按合盖、电池、供电显示未开放/请接电，否则「尚未开启」。剩余：检查窗口与托盘实际文案、拔电与电源未知显示 |

已确认的源码对齐项：欢迎页明确接电开盖、合盖/电池未开放与热保护不可用；能力说明没有伪造热状态；选择接电合盖和有网时保留各自原始选项，核心阻止合盖，不自动取消条件；登录 `--startup` 已完成引导时不显示窗口，未创建活动会话；关闭窗口取消关闭并隐藏，设置页说明常驻托盘；停止或退出撤下遮罩，设置页明确没有服务和合盖设置修改。

这些确认仅证明代码意图。柔光托盘可操作、关闭窗口后托盘存在、锁屏事件正常送达、登录静默窗口和实际系统请求释放，需要 Windows 原生操作验收。柔光采用 WorkingArea，任务栏预留区域不覆盖；自动隐藏任务栏、多屏与 DPI 组合必须人工验证，不能仅凭源码推断全部成立。
