# 三视角体验评审（2026-10-13）

用户要求从 AI 使用者、产品经理和 UI 设计师三个视角审视项目并做一轮优化。本文是源码与文档阅读后的评审，以及本轮实际改动范围；不是用户访谈或真机可用性测试。验证结果见 status.md 同日记录。

## 典型用户旅程

晚上 23:00，用户让 Claude Code / Codex 跑一个重构或长测试，选“夜间”开始保活后去睡觉；早上回来先想知道两件事：**任务是不是一直有条件运行**，以及**保活什么时候、因为什么停的**。之后才会去看 AI 任务本身的结果。本产品只负责运行条件，不判断任务是否完成。

## AI 使用者视角

| 发现 | 影响 | 本轮处理 |
| --- | --- | --- |
| 只显示倒计时 `07:59:12`，要心算几点结束 | 睡前无法确认“8 小时够不够跑到早上” | 两端运行中显示“预计明天 07:10 结束”；无限时显示“直到手动停止” |
| 停止原因只写在一次性消息里；Mac 切换场景会把它覆盖为“未开启” | 早上回来看不到昨晚何时、为何停止 | 两端保留“上次 23:10–07:10 · 运行 8 小时 · 设定时间已到”，切场景不清除，下次开始后隐藏 |
| Mac 欢迎页写“下载、构建和远程工作”，没提 AI 任务 | 核心用户读不出这是为谁做的 | 欢迎页改为 AI 编程、构建、下载；明确不改变锁屏、不判断任务完成 |
| 普通模式运行提示“合盖需开启合盖模式” | 用户想知道“现在能不能锁屏走开” | Mac 改为“不影响锁屏，请保持开盖”；Windows 改为“请保持开盖；不改变锁屏策略”。只描述设计行为，Windows 锁屏下的任务持续仍待真机验收 |

## 产品经理视角

- [Windows 产品评审](product-review-windows.md) P1 第 1、3 条（结束时刻、保留结束原因）原先没有在任何一端落地；本轮两端同时实现，措辞由两端相同的单元测试锁定。
- Mac 场景默认值原先硬编码在 `AppModel.chooseScene`，与 `specs/scenes.json` 只做“合法性”校验，存在漂移风险。现移到 `macos/core/SessionText.swift` 的 `ScenePreset`，契约测试逐字段比对共享数据。
- Mac 待机标题恒为“随时准备好”，即使未接电或合盖组件未批准，点了开始才报错。现在待机标题直接给出阻塞原因（请接通电源 / 合盖需先批准组件 / 此版本不支持合盖），与 Windows 已有行为对齐。
- 结果保留在内存中：App 退出或重启后不保留上次结果。是否持久化、是否发系统通知，留待用户决定（见下方待定）。

## UI 设计视角

| 发现 | 本轮处理 |
| --- | --- |
| Mac 菜单栏倒计时 8 小时显示为 `480m` | 改为 `7h59m` / `45m`，等宽数字，宽度稳定 |
| Mac 待机副标题“选好场景，一键开始”不说明将要做什么 | 改为配置摘要：“夜间 · 8 小时 · 开盖 · 仅接电 · 夜间柔光”；改过参数标注“（已调整）” |
| Mac 场景提示语（“专心长任务”“柔光伴你休息”）只在悬停时可见且不含规则 | 悬停提示改为该场景的实际规则摘要；选中场景加入辅助功能 selected 属性 |
| Windows 四个场景按钮没有选中态，只能读副标题判断当前场景 | 选中按钮加暖铜描边、浅底和加粗，读屏报告“已选择”；亮色、暗色、高对比度主题均有对应画刷 |
| Windows 配置摘要“480 分钟”、缺屏幕模式 | 与 Mac 同序：“8 小时 · 开盖 · 仅接电 · 夜间柔光”；Windows 合盖仍写“请求合盖”以示未开放 |

## 待定与后续建议

以下内容涉及产品方向或需要真机验证，本轮没有实现：

1. **“有网时”场景命名。** 实际含义是“电池合盖、断网停止”，名字只说了条件的一半；可考虑“外出合盖”等。改名影响已保存偏好和双端合约，需要用户拍板。
2. **结束通知与结果持久化。** macOS 用户通知、Windows 托盘气泡可以在会话结束时留一条系统记录；上次结果也可以跨重启保存。需要决定是否请求通知权限。
3. **Windows 首次关闭窗口提示。** 产品评审 P1 第 4 条：首次关窗时用托盘气泡说明“仍在托盘”。需要 Windows 真机检查气泡行为。
4. **AI 任务绑定。** 产品范围已把“任务绑定、可验证的 AI 任务事件接入”列为后续阶段；第一版仍不根据 CPU、输出或窗口推断任务完成。

## 本轮未验证

- Mac SwiftUI 变更在 Linux 上无法编译；需要 macOS CI 或本机 `swift test` 和 `./scripts/build-macos.sh`，并实际查看菜单栏宽度、副标题换行和上次结果行。
- Windows WPF 选中态、主题画刷和新增注入检查仅在 Linux 交叉编译，需要 Windows runner 或真机执行 `windows/app-tests/`，并目视检查三种主题。
