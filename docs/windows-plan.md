# Mac / Windows 双端产品方案

日期：2026-10-13。状态：最初方案及本轮实现边界。用户随后授权服务器开发，普通预览源码已实现，真机工作按 [Windows 交接](windows-handoff.md) 接续。

## 用户目标与本轮范围

用户希望宣传现有应用时，看到内容的 Windows 用户也能下载使用；两端体验尽量接近。先定方案后，用户授权在服务器开发 Windows 并重构整个仓库，依赖真机的部分留待本地。核心需求进一步明确为 AI 工作在合盖或用户夜间休息时持续运行。Windows 是同一产品的另一端，面向普通用户，不要求输入命令；本轮不安装服务或发布发行物。

产品主张建议统一为：**工作继续，安心休息。** 用户设定一次保活会话，离开电脑后任务继续运行，到期或触发保护时撤销本应用保活。离线任务和联网任务都适用；网络条件由用户选择。

## 名称与宣传入口

- 保留现有 KeepMyMacAwake 名称、仓库和 Mac 安装路径。
- 用户要求暂缓改名，Windows 沿用 KeepMyMacAwake 品牌并标明 Windows；不采用先前建议的 KeepMyWindowsAwake 或其他候选。
- 使用同一介绍页，提供 Mac / Windows 两个下载入口、各自版本与支持范围；允许用户手动选择另一系统。
- 两端沿用杯子图标、暖铜色视觉、主文案与场景名称。不同系统的安装授权另写说明。
- 当前仅有构建脚本生成本地未签名 Windows 体验包，没有公开 Windows Release。界面和说明标注开发预览，不宣称已经完成真机支持。

## 两端统一的产品规则

一致的是用户操作、会话语义与停止原因；菜单栏、托盘、授权方式按平台适配。

| 项目 | 双端目标 |
| --- | --- |
| 常驻入口 | Mac 菜单栏、Windows 系统托盘；点击可打开控制窗口 |
| 页面 | 保活 / 设置；启停按钮固定可见 |
| 日常 | 1 小时、仅接电、允许自动熄屏、不要求网络 |
| 夜间 | 8 小时、仅接电、开盖、夜间柔光 |
| 接电合盖 | 直到手动停止、仅接电、合盖前确认后端就绪 |
| 有网时 | 2 小时、允许电池、要求网络路径、请求合盖；能力不满足时阻止启动并说明 |
| 时长 | 30 分钟、1 / 2 / 8 小时、自定义 1–1440 分钟、直到手动停止 |
| 续时 | 活动有限时会话加 15 分钟，累计不超过 24 小时；已结束不能续活 |
| 屏幕 | 自动熄屏 / 保持常亮 / 夜间柔光；柔光是临时画面遮罩，不是硬件亮度 |
| 保护 | 默认仅接电；电池模式显式选择，下限默认 20%、范围 10–80%；所需数据未知时不能启动或停止当前会话 |
| 网络 | 展示路径可用性，不冒充互联网或任务服务可达；仅选中网络条件时断网停止，联网后不自动重启 |
| 偏好 | 保存已校验设置；启动恢复偏好，不自动恢复活动会话 |
| 生命周期 | 关控制窗口留在常驻入口；退出停止保活；系统设置恢复失败必须明确显示 |
| 锁屏 | 不模拟键鼠、不改锁屏策略；锁屏后持续运行须单独验收 |
| 登录启动 | 用户可选；静默显示常驻入口，保持待机 |

上表沿用 Mac 当前场景默认值，不代表 Windows 已具备这些能力。场景选项不能悄悄删掉合盖、网络或保护条件再启动。后端能力不满足时保持未开启，展示原因和用户可显式选择的其他模式。

## 能力差异如何呈现

| 能力 | Mac 当前实现 | Windows 方案与验收门槛 |
| --- | --- | --- |
| 普通防闲置休眠 | IOPMAssertion | 公开 Power Request API，系统与显示请求分开；不修改常规睡眠超时 |
| 合盖 | helper 修改 SleepDisabled；物理矩阵未完成 | 固定电源设置 API 临时管理合盖动作；需要恢复服务和机型验证 |
| 电源 / 电量 | IOPowerSources | 系统电源状态与通知；无电池的接电桌面机可用 |
| 网络路径 | NWPathMonitor | Windows 网络状态接口；与 Mac 保持检测范围一致 |
| 热保护 | ProcessInfo 热状态 | 本轮未建立适用于所有 Windows 机器的可靠数据源；显示“热保护不可用”，不能冒充正常 |
| 夜间柔光 | 临时 AppKit 多屏窗口 | 临时多屏遮罩，保留托盘与控制窗口操作；验证缩放、多显示器、锁屏和全屏切换 |
| 系统授权 | SMAppService 与本人认证 | 安装恢复组件时按系统需要请求 UAC；普通界面与任务不提升权限 |

Windows 热状态数据来源是合盖开放前的决策门槛。若可靠来源不存在，需要另行明确保护标准和风险说明；本轮不默默删除 Mac 的保护要求、不承诺 Windows 同等热保护。保护策略明确要求某项监控时，缺失数据必须阻止启动或停止，不能用 UI 提示替代保护。

Windows 电池上的 Modern Standby 存在系统级电源请求时限，因此“有网时”的电池运行不能仅凭 API 返回成功开放。接电普通模式、接电合盖、电池普通模式、电池合盖分别记录支持结果。网络有无与电源后端是否受支持分别判断。

## Windows 实现路线建议

采用 Windows 原生 C# / WPF，Mac 保持 SwiftUI / AppKit。WPF 可实现接近现有卡片、计时环、设置页的界面，同时保留 Windows 的窗口、缩放、键盘与可访问性交互。这是技术建议，尚未建立工程或决定运行时版本。

代码放在同仓库小写 `windows/` 下，按应用、纯逻辑、系统后端、服务、测试组织；现有 Mac 放在 `macos/`，根 Swift / 构建入口兼容保留。Mac 不为新增平台重写。双端共用 `specs/` 产品场景及行为测试数据，Swift / C# 分别实现逻辑；未知遥测与平台能力差异用各自测试单独覆盖。

普通保活先验证 PowerCreateRequest / PowerSetRequest / PowerClearRequest 的创建、释放及崩溃后的生命周期。句柄由保活进程拥有，不把请求重复计数用作续时；有限会话的截止时刻独立于系统请求。睡眠、恢复和系统时间跳变都要重新检查，不能从待机醒来后自动续跑已失效会话。

合盖作为独立后端设计：

1. 读取当前电源方案 ID、合盖 AC / DC 原值、管理策略与所需遥测。不复制或替换整套电源计划。
2. 固定 API 只修改本次模式需要的合盖值；写前记录方案 ID、原值、目标值、所有权与恢复意图，读回确认后显示就绪。
3. 普通用户 App 与独立恢复服务以版本化固定协议通信。授权绑定本机用户、客户端身份、连接与随机会话令牌；不提供命令、路径或任意设置写入接口。服务文件、通信和记录目录的权限单独验证。
4. 沿用 5 秒心跳、20 秒失联截止、2 秒巡检作为初始目标；服务独立执行截止与保护。服务崩溃或重启先恢复，不继续旧会话。
5. 电源计划切换或外部设置变化时停止并只恢复仍能确认归属的字段；不切回用户已更换的电源计划、不覆盖管理员策略。相同值的第三方写入无法可靠归属，需记录这一边界。
6. 退出、强杀、重启、升级、卸载均验收恢复；升级或卸载前停止并确认恢复。不能只依赖退出回调或下一次启动 App。

服务注册、签名校验细节、策略检测、设置实际生效与恢复机制均需 Windows 实验确定；本方案不是已经验证的实现。

## 开发顺序与交付标准

建议首个验收对象为受支持 Windows 11 的 x64 笔记本和桌面机。ARM64、其他系统版本另列，不能根据交叉编译宣布支持。

| 阶段 | 产出 | 可对外表述 |
| --- | --- | --- |
| 1：普通保活预览 | 托盘 / 控制窗口、计时与续时、日常 / 夜间、屏幕模式、供电与网络条件、偏好与停止原因；未开放的场景显示原因 | Windows 开发预览，列出实际可用功能与不支持项 |
| 2：合盖与独立恢复 | 接电合盖、固定协议服务、授权、恢复记录、故障与卸载验证；解决热保护标准 | 仅对通过矩阵的机型和条件开放合盖；电池单独验收 |
| 3：双端宣传交付 | 自包含 Windows 图形安装包、版本与下载说明、签名 / 系统信誉提示验收、双端下载入口 | 两端均可下载，并分别声明支持范围 |

普通用户不需要自行安装开发工具或输入命令。首次安装显示控制窗口；登录启动不自动保活。Windows 安装包随附所需运行时，服务通过图形化安装授权。签名与 SmartScreen 实际结果必须记录，签名本身不等于已建立下载信誉。

只有阶段 1 时，宣传不能笼统承诺“双端合盖功能一致”。面向当前 Mac 合盖宣传的完整 Windows 交付需阶段 2、3完成；无需等待全部型号通过，但要有明确的实际支持范围。

## 验证与下一步

- 纯逻辑：有限 / 无限会话、累计时长上限、到期不可续活、断网后不重启、未知遥测、时钟跳变、偏好校验、方案切换与恢复故障注入。
- Windows CI：构建 UI / 服务，运行 Windows 后端可自动化检查，打包体验产物；CI 不计作物理合盖验证。
- 真机：接电熄屏、锁屏、夜间多屏、无网络任务、接电合盖、拔电、断网、Modern Standby、电池边界、App / 服务强杀、重启、升级与卸载。
- 记录机型、Windows 构建、睡眠模型、供电、外设、提交号、测试时长、连续任务心跳与前后设置。不得人为过热来测试保护。

本轮实际检查见 [status.md](status.md)。当前普通预览只开放接电开盖；因为没有可靠通用热数据，明确使用“无应用热保护”的能力配置，不伪造正常热状态。合盖和电池能力硬关闭，原场景不能静默降级。恢复服务的生产身份与安装信任尚未完成，启动硬拒绝，用户包不包含服务。下一步在 Windows 本地完成普通模式验收、服务信任链、合盖恢复、Modern Standby 与热遥测实验。

## 官方依据

查阅日期：2026-10-13。下面区分文档语义与产品设计；以上工程路线属于本项目建议。

- [PowerToys Awake](https://learn.microsoft.com/en-us/windows/powertoys/awake)：现有保活模式及其锁屏限制；此限制不能直接外推为所有 Windows 保活实现的限制。
- [PowerSetRequest](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-powersetrequest)：系统 / 显示请求、Modern Standby 电池时限和主动睡眠边界。
- [PowerCreateRequest](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-powercreaterequest)：创建电源请求对象与关闭句柄。
- [Lid switch close action](https://learn.microsoft.com/en-us/windows-hardware/customize/power-settings/power-button-and-lid-settings-lid-switch-close-action)：Windows 合盖动作设置。
- [PowerWriteACValueIndex](https://learn.microsoft.com/en-us/windows/win32/api/powersetting/nf-powersetting-powerwriteacvalueindex)：定向写入电源方案的 AC 设置；活动方案修改需要激活后生效。
- [System Power Status](https://learn.microsoft.com/en-us/windows/win32/power/system-power-status)：系统供电、电池信息与电源通知。
- [WPF overview](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/)：Windows 原生桌面界面、样式与布局能力。
