## 2026-10-10：Mac 场景版与协议 v2

- 根据用户新要求，增加 duration = 0 的无限时会话；有限时会话保持 1–1440 分钟范围。取消无限时会话的 24 小时截止，但仍执行连接所有权、20 秒失联、保护停止与崩溃恢复，不通过重新获取租约制造恢复空窗。
- App/helper 协议升级到 v2，增加网络条件和监控字段，拒绝混用 v1 组件。两端独立运行 NWPathMonitor；helper 不信任 UI 报告的网络状态。未知网络在启用网络条件时停止。
- 本机 macOS 26.4.1 的 pmset -g 不显示未设置的 SleepDisabled；缺失时改为读取 IOPMrootDomain 的明确 CFBoolean 属性，拒绝缺失或类型错误。Apple [pmset 源码](https://github.com/apple-oss-distributions/PowerManagement/blob/main/pmset/pmset.m)只在配置有该键时打印；[内核源码](https://github.com/apple-oss-distributions/xnu/blob/main/iokit/Kernel/IOPMrootDomain.cpp)发布与处理此布尔属性。本机只读验证通过；实际写入与合盖仍待验收。
- 夜间使用临时 AppKit 窗口遮罩，未引入私有亮度 API 或持久化亮度改动。明确展示“画面变暗”，不冒充硬件背光调节。通过公开 [显示防闲置断言](https://developer.apple.com/documentation/iokit/kiopmassertiontypepreventuseridledisplaysleep)控制屏幕常亮，结束时释放。
- 本机证书构建发现 codesign -R 把裸字符串当作文件路径，校验改用以等号开头的显式 requirement 字符串；保持双向签名校验。
- App 本地保护每秒检查，helper XPC 心跳仍每 5 秒；计时器加入 common RunLoop 模式，减少交互影响。

## 2026-10-10：0.2.0 安装与主分支交付

用户已明确授权本机安装、所需系统授权、测试后推送并合入 main。沿用系统 SMAppService 安装流程，不通过手工 sudo 常驻进程或放宽签名要求替代。

- 增加原生控制窗口，保留菜单栏主入口与 LSUIElement，首次启动／Finder 重新打开可发现；关闭窗口不结束会话。
- 原生 UI 使用暖铜色杯子和计时环，自绘 ICNS，不增加第三方 UI 依赖。控制按钮固定在滚动区外，所有场景都能随时停止。
- UserDefaults 仅保存已校验的使用偏好；测试注入独立 defaults，运行会话不持久化。
- 协议 v3 新增固定 extend 操作。延长必须属于同一连接、旧会话仍有效，且总有限时长不超过 24 小时；不通过停止再开始造成合盖恢复空窗。
- 原生测试可注入时钟和监控样本，对真实 IOPMAssertion 验证自动到期和网络保护后的释放；保护样本注入不能计作拔电／断网的物理验证。
- 不声明自动化可操作物理盖子。签名、授权、设置读回、开盖持续运行和物理合盖分别记录。

- 本机 SMAppService 注册返回 EPERM 后状态实际已是 requiresApproval。保留该注册状态，直接显示本人认证引导；只有未进入待批准状态的错误才显示授权失败。系统认证提示需要本人触控 ID／密码，不能用开发授权替代系统身份认证。
- CI 的旧 Swift 拒绝在屏幕变化回调的 Task 中再次捕获可变弱引用；回调先展开成不可变引用再切换到 MainActor，保持弱观察者、不形成循环引用。

## 2026-10-11：后台监测与界面更新分离

`refresh()` 原先每秒切换公开的 `busy`，XPC 等待期间使按钮变为“正在处理”并禁用控件；相同采样和状态也反复触发 `objectWillChange`。改为仅用户操作发布 busy，后台请求用私有标志避免重入；轮询仅发布发生变化的值，仍保持每秒本地保护与每五秒 helper 心跳。

后台等待不再锁住操作，因此每次启停、续时、授权和恢复递增操作代数。较旧轮询的成功或失败结果均不能覆盖较新的用户操作。测试可注入 helper 状态和异步回复，并关闭自动计时器；默认生产路径仍使用真实 SMAppService 和签名 XPC。

屏幕变化通知不代表显示器一定变化。夜间遮罩按显示器 ID 复用，只在尺寸或透明度实际变化时更新，新增／移除显示器时增删对应窗口；停止后忽略排队通知，避免撤掉再重建导致亮闪或停止后遮罩重现。通过真实 AppKit 窗口身份与可见性测试验证重复通知路径；不能代替物理多屏切换验收。

## 2026-10-13：双端产品方向与 Windows 方案

用户明确希望支持 Windows，并使两端体验尽量接近，便于同一宣传入口覆盖两端用户；本轮明确选择先定方案，不开始 Windows 编码。

- 用户确定的方向：Windows 作为同一产品的另一端，保持普通用户图形入口、相近的场景、计时、启停与状态语义。
- 方案建议：保留 Mac 原生实现，Windows 使用 C# / WPF；同仓库 `windows/` 下组织，共用产品规则与测试案例，不在本轮重写 Mac 或引入跨端 UI 框架。
- 技术方案与工作名称尚未由用户确认。Windows 合盖恢复、热保护来源与 Modern Standby 电池边界需技术实验，不凭 API 返回成功宣布支持。
- 先完成普通预览，再合盖恢复与真机验收，最后形成双端下载交付；Windows 工作名称建议 KeepMyWindowsAwake，保留现有 Mac 名称。

具体体验对齐表、能力门槛、开发顺序与验证范围见 [双端方案](windows-plan.md)。现有 Mac 支持边界保持以实际验证记录为准。

- 本轮产物为自包含、未签名 Windows ZIP，只含普通用户 App、说明、许可证；服务只编译、不安装、不进入用户包。正式图形安装器、签名与系统信誉、本机合盖验证留后续。

## 2026-10-13：结束时刻与上次结果

AI 长任务用户最常问的是“几点结束”和“回来时它为什么停了”。两端增加两条展示，不改变会话判定：

- 预计结束时刻按开始墙钟加计划时长（续时同步增加）展示；截止判定仍使用含睡眠时间的连续时钟。时钟明显跳变时会话照旧以 clockChanged 停止。
- 上次结果在会话结束的同一处记录（到期、保护停止、手动停止、后台报告结束、系统休眠），只保存在内存。暂不持久化、不发系统通知，避免引入通知权限和陈旧记录；是否增加留待用户决定。
- 文案由 `macos/core/SessionText.swift` 与 `windows/core/SessionText.cs` 生成，两端单元测试使用相同用例。Mac 场景默认值同步移到核心 `ScenePreset`，以便契约测试直接比对 `specs/scenes.json`。

## 2026-10-15：界面重设计、术语表与菜单栏信息面板

用户反馈保活效果好用，要求界面更精美、名词更准确、交互更顺，并在状态栏用小图标查看信息；完成后推送并优化仓库介绍。

- **术语以系统行为为准。** macOS / Windows 中文都把 sleep 称为“睡眠”、hibernate 称为“休眠”，界面统一改用“睡眠”。产品动作叫“保持唤醒”（不再用开发者口语“保活”）；空闲状态叫“未开启”，不用“待机”（中文“待机”易被理解为 standby，正好与本应用相反）。
- **显示名与存储标识分离。** 屏幕模式显示为“允许熄屏 / 屏幕常亮 / 调暗常亮”，偏好与 `specs/scenes.json` 继续保存“自动熄屏 / 保持常亮 / 夜间柔光”和 C# 枚举，不迁移旧偏好。“柔光”改为“调暗”，因为实际是保持屏幕点亮再加软件暗色遮罩，不是硬件亮度或光线调节。
- 其他对照：仅接通电源时保活 → 仅在接通电源时运行；保护条件 → 自动停止条件；热状态/热压力 → 散热状态（正常/略高/较高/严重，对应 ProcessInfo.ThermalState，不是温度读数）；恢复设置 → 恢复睡眠设置；停止并移除组件 → 停止并卸载后台组件；安装 / 检查授权 → 按状态显示“安装后台组件 / 前往系统设置授权 / 重新检查连接”之一；再加 15 分钟 → 延长 15 分钟；摘要中的“开盖 / 合盖 / 允许电池”→“需开盖 / 可合盖 / 可用电池”。
- **菜单栏面板从“缩小版控制窗口”改为信息面板。** 原面板与控制窗口内容重复、390×620 偏大。新面板 320pt 宽、按内容定高：状态与剩余/已运行时间、开始时刻、规则摘要、电源/网络/散热、合盖组件（相关时）、上次结束，以及场景切换、开始/停止/延长和打开窗口入口。菜单栏图标用形状区分状态（空杯/实心杯/警示三角），不只依赖颜色。
- 无限时会话的“已运行”计时只由视图的 `TimelineView` 刷新，模型不为未变化状态发布更新，保留 0.2.1 防闪动回归。
- **首次使用不再拦截。** 原欢迎页只有“开始使用”一个动作，属于多余一步。改为控制页顶部可关闭的“使用须知”卡片；第一次开始会话即视为已读。注意事项内容（通风、不改锁屏、不判断任务完成、合盖需授权）保持不变。
- 未签名构建的提示从“此版本不支持合盖”改为说明原因：“未签名构建无法合盖”，并指向签名版本；避免用户误以为产品不再支持合盖。
- 主按钮改为 SwiftUI 自绘样式，浅/深色下使用不同的前景色保证对比度；离屏渲染也能稳定输出，用于 README 截图（`ScreenshotTests`，需设置 `AWAKE_SCREENSHOTS` 才执行）。

## 2026-10-15：去掉“AI 味”的文案与系统强调色

用户看完 0.3.0 后指出“可以开始”这类文字没有必要、AI 味重，不像精致的原生软件；又指出铜橙配色接近 Claude Code 常用色调，同样有 AI 感。用户要求由子 agent 评审后再优化。评审以资深 Mac 设计师与中文界面文案视角逐张看截图、通读文案，结论按以下原则落实：

- **只写用户需要的信息。** 删除标语、头部状态徽章、使用须知卡、页脚提示、控件下的解释行与所有成功提示（已延长、已停止、已就绪等）；消息区只显示错误和需要用户处理的事，下一次成功操作后清空。空闲标题直接写“未开启”，或用橙色写出阻止原因。
- **同一信息只出现一次。** 场景名只由选中的场景卡表达；“已调整”只在“选项”标题旁；“上次结束”压成一行，完整时段放悬停提示。运行中用只读的“本次会话”信息卡替代整片置灰的控件。
- **用词与标点。** 按钮用动词短语：开始、停止、+15 分钟、恢复睡眠设置、安装后台组件、卸载后台组件…（带确认）。状态：未开启、剩余、已运行、正在确认…、睡眠设置未恢复。屏幕：自动关闭 / 常亮 / 调暗；时长“不限时”。停止原因是简短事实短语，不带“请…”、不加句号（时间到、手动停止、电源已断开、电量达到下限、App 无响应、散热状态严重等），同一短语用于上次结束、通知和阻止原因。“·”只用于最多两项的状态信息；系统路径写作“系统设置 > 通用 > 登录项与扩展”；“后台组件”为唯一叫法；“登录时打开”与系统设置用词一致。
- **必要提醒保留但只放一处或放到悬停提示。** 运行时状态卡写“可以合盖”（悬停：请放在通风处）或“可以锁屏，请勿合盖”；调暗不调硬件亮度、网络只代表系统有可用路径、散热是系统等级不是温度，都改为悬停提示；“不代表 AI 任务已完成”只留在通知开关下；“删除 App 前请先卸载后台组件。合盖运行时请放在通风处。”只留在设置页后台组件组。未知数据仍显示“未知”并以橙色标出。
- 评审发现的错误一并修正：读不到网络或电量时也会返回 telemetryUnknown，原因从“无法读取电源或散热状态”改为“无法读取电源、网络或散热状态”。
- **配色跟随系统。** 界面强调色改用 `NSColor.controlAccentColor`，跟随用户在“系统设置 > 外观”中选择的颜色（默认蓝色），与系统自带 App 一致；橙色只用于警告，绿色只用于“可以合盖”。App 图标改为深蓝夜色渐变、白色杯子、浅蓝蒸汽与月牙，不再使用暖铜色。
- Windows 本轮未改：它的文案与配色仍为上一版，待下一轮按同一用语表与系统强调色对齐，并重新生成 Windows 界面报告。

## 2026-10-15：中性配色与“精品 Mac 软件”质感（0.4.0）

用户认为系统蓝强调色用得太多、不好看，整体质感不足；参考 nowdex.app 的质感（不要求照搬风格），希望有“有 AI 之前那种精品 Mac 软件”的高级感。本节取代上一节“配色跟随系统”的做法。

- **几乎不用彩色。** 页面为暖灰近白底（深色为近黑），内容放在白色（深色为抬升灰）卡片上，发丝细边框与极轻阴影；主按钮、选中场景与刻度为近黑“墨色”（深色模式为近白）；开关为石墨灰。颜色只用于状态：绿色圆点表示运行与“可以合盖”，橙色表示警告/阻止原因，红色表示睡眠设置未恢复。
- **数字是主角。** 圆环换成大号细字重数字配小号单位（6 小时 28 分；最后一小时显示分、秒），下方是按宽度计算格数的细刻度条；未开启时大数字直接显示本次将运行多久，旁边只列一到两项值得注意的规则。
- **自绘控件。** “控制 / 设置”与屏幕模式改为胶囊切换（凹陷轨道 + 抬升选中块），菜单栏面板标题右侧为圆形图标按钮（更多选项、设置、退出，标签在悬停提示与读屏中），场景切换为胶囊。
- **窗口贴合内容。** 控制窗口按页面实际高度自动收放（不超过可见屏幕），运行中与设置页不再留下大片空白；测量放在 GeometryReader 的 onAppear/onChange 中，因为 ScrollView 内的 PreferenceKey 在本机读回为 0。
- App 图标改为石墨黑渐变、白色杯子与浅灰蒸汽、月牙。
- Windows 仍未对齐，下一轮按同一套中性配色与用语调整并复核界面报告。
