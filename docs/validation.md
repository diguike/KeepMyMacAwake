# 验证与本地 Mac 交接计划

Linux 已执行纯逻辑与恢复文件测试；所有物理 Mac 场景仍待执行。具体结果见 status.md，操作顺序见 mac-handoff.md。

## 环境边界

| Linux 服务器可做 | 必须在 Mac 做 |
| --- | --- |
| 文档、源码、状态机设计、协议与逻辑测试设计 | SwiftUI / AppKit / IOKit / ServiceManagement 构建 |
| 有可用工具链时测试不依赖 Apple 框架的纯逻辑 | helper 授权、XPC 身份验证、真实电源设置 |
| 静态检查、链接与目录检查 | 合盖行为、锁屏、供电切换、散热与网络 |
| 准备构建和测试说明 | Developer ID 签名、公证和安装包验收 |

macOS CI 可验证编译和部分逻辑，但不能替代有物理合盖传感器的 MacBook。

## 真机记录字段

每次测试记录：日期、App 版本／Git 提交、芯片与型号、macOS 版本和构建号、供电、外部显示器／诱骗器、输入设备、授权状态、锁屏状态、网络／VPN、其他保活工具、测试时长、期待结果、实际结果及脱敏日志。

## 验证矩阵

| 场景 | 需要证明 |
| --- | --- |
| 普通保活，开盖熄屏 | 系统继续运行，屏幕可以关闭 |
| 无外接屏，接电合盖 | 连续任务心跳和请求持续，日志无意外休眠 |
| 无外接屏，电池合盖 | 显式电池模式生效，保护下限有效 |
| 合盖时拔插电源 | 默认仅接电模式停止；电池模式按策略维持或解释失败 |
| 真显示器、诱骗器接入／移除 | 检测变化，不能展示失效保活为正常 |
| 锁屏 | 仍可锁屏，保活不模拟输入绕过锁屏 |
| 计时到期、手动停止、退出 | 改动恢复，状态准确 |
| UI kill -9 / 卡死 | helper 在限定时间内恢复 |
| helper kill -9 / 重启 | launchd 恢复服务并清理遗留记录 |
| 改动后立即重启 | 基线恢复，不自动续跑旧会话 |
| 多租约、令牌错误、未授权客户端 | 不提前恢复，不允许越权操作 |
| 其他保活工具已开或中途修改 | 不夺取所有权，报告冲突 |
| 电量下限、热状态、连续读取失败 | 触发明确停止，不反复重启 |
| VPN／Wi-Fi／热点断开 | 独立显示网络问题，不误报电源错误 |
| App 升级、移动、移除 helper | 设置恢复，后端注册与版本行为明确 |

先测 Apple Silicon Air 与 Pro；不同受支持系统版本各保留记录，Intel 单独列为扩展。不要以单台机器成功宣布支持所有 Mac。

## 验收证据

读回 SleepDisabled 只能说明设置状态；返回成功或图标亮起均不足以证明合盖保活。
需要同时使用连续任务心跳、按间隔发出的网络请求、合盖前后时间戳和电源日志。网络失败应单独分析，不能全部归因于休眠。

未来 Mac 上的只读诊断入口：

```sh
sw_vers
uname -m
pmset -g
pmset -g assertions
pmset -g batt
pmset -g log
```

这些是诊断命令，不是本项目构建命令；未在当前服务器执行。日志采集限制时间窗并脱敏。真实低电量和热状态的危险边界优先通过可注入的监控样本验证，不人为制造过热。
